# ルーラと裁ちトンボ

どちらも「表示」タブで出し入れする。設定は端末に覚えるので、次に起動したときも同じ状態で開く。
ネイティブメニューの「表示」からも切り替えられる。

| | 既定 | 効く範囲 |
|---|---|---|
| ルーラ | 出す | 画面だけ |
| 裁ちトンボ | 出さない | **画面と PDF の両方** |

どちらも印刷レイアウト表示のときだけ出る。下書き表示には紙が無いので出しようがない。

---

## ルーラ

余白と本文領域の境、段落の字下げを目盛りで見せる。横と縦の 2 本。

### 目盛りの読み方

**原点は本文領域の左端**で、紙の端ではない。書いている人が知りたいのは
「余白からどれだけ下げたか」であって「紙の端からの距離」ではないため。Word も同じ。
余白の中に入ると数字は戻っていく (3, 2, 1, 0) が、符号は付けない。

単位は **mm**。日本語 Word の既定は「字」だが、字の幅は書体と級数で変わるので、
紙に出たときの長さと一致しない。裁ちトンボと同じ mm にそろえておくと、
入稿するときに読み替えが要らない。

数字は 10mm ごと、細かい目盛りは 5mm ごと。

### 字下げを変える

横のルーラにつまみが 4 つある。つかんで動かすと、カーソルのある段落の字下げが変わる。
0.5mm 刻みで吸い付く。つまみにカーソルを合わせると、いまの値が mm で出る。

| つまみ | 形 | 位置 | 動くもの |
|---|---|---|---|
| 1 行目の字下げ | 下向きの三角 | 上段 | 1 行目だけ |
| 2 行目以降の字下げ | 上向きの三角 | 中段 | 2 行目以降だけ (1 行目はその場に残る) |
| 左の字下げ | 四角 | 下段 | 段落全体 |
| 右の字下げ | 上向きの三角 | 中段 (右) | 右端 |

**つまみは字下げが 0 のとき 3 つとも同じ位置に重なる。**
当たり判定を上下の段で分けてあるのはそのため。分けないと、上の三角をつかんだつもりで
下の三角が動く (実際にそうなった)。

縦のルーラはつかめない。上下の余白はページ設定で変えるもので、
段落ごとに変わる字下げとは性質が違う。

### 紙 1 枚につき 1 本

縦のルーラは紙ごとに目盛りを振り直す。文書全体で 1 本にすると、
2 ページ目の上端が 297mm から始まってしまい、定規として読めない。

### 倍率との関係

倍率は `transform` ではなく座標に掛けている。`transform` で拡大すると線も数字も太り、
目盛りとして読めなくなるため。紙のほうは `transform` で拡大しているので、
両者は別々の道筋で同じ倍率に合わせている。

## 裁ちトンボ (トリムマーク)

印刷所に入稿するとき、紙は仕上がりサイズより大きく刷って断裁する。
どこで断つかを示す印がトンボ。

### 形

- **角トンボ** … 四隅の二重のカギ線。内側が仕上がり線、外側が塗り足し線 (3mm 外)
- **センタートンボ** … 各辺の中央の十字。断裁機の位置合わせに使う

内側の線は**仕上がりの角に届かせない**。塗り足しぶん手前で止める。
断裁の線そのものを紙に印刷すると、断ち切れずに残ったとき製品に線が出る。

### 寸法

| | 値 |
|---|---|
| 塗り足し | 3mm (日本の印刷所はほぼこれで統一されている) |
| トンボの線の長さ | 10mm |
| 用紙の増分 | 四辺それぞれ 13mm |
| 線の太さ | 0.2mm |

A4 (210 × 297mm) なら用紙は 236 × 323mm、
A5 (148 × 210mm) なら 174 × 236mm になる。

線の太さは印刷の慣例 (0.1mm 前後) より少し太い。0.1mm では画面で見えないため。
0.2mm は断裁の精度 (±1mm 程度) に対して十分細い。

### 本文の位置は動かない

トンボは紙の**外側**に足すものなので、本文の位置は変わらない。
画面では紙が四辺に広がり、本文はその中央に残る。改ページ位置も PDF も変わらない。

画面でこれを成り立たせるために、ページ間の隙間をトンボのぶんだけ広げている。
広げないと隣の紙とトンボが重なる。広げたぶんはスペーサーの高さにも効くので、
本文が落ちる位置はそのまま保たれる。

### PDF

**画面に出していれば PDF にも入る。** Wowd は「画面の見た目と PDF が一致する」ことを
構造で保証しているので、ここだけ別扱いにしない。
PDF の用紙サイズもトンボ込みの寸法になる (A4 なら 236 × 323mm)。

### 色について

線は黒で描く。印刷所に出すなら本式はレジストレーションカラー (CMYK 4 色 100%) だが、
それは PDF を CMYK で作れる場合の話で、Wowd が出すのは RGB の PDF なので黒にしてある。
4 色分解は印刷所側の工程になる。

## 作りの分け方

寸法の計算は DOM に依存しない純粋関数として `src/core/layout/` に置き、
描画だけを画面側に置いた。単体テストで総当たりできるようにするため。

| | 計算 | 画面 | 印刷 |
|---|---|---|---|
| ルーラ | `src/core/layout/ruler.ts` | `src/renderer/components/Ruler.tsx` | 出さない |
| 裁ちトンボ | `src/core/layout/trimMarks.ts` | `src/renderer/editor/pagination/PageChrome.tsx` | `src/core/css/printHtml.ts` |

トンボの図は画面も印刷も**同じ関数**が作る。別々に描くと線がずれ、
どちらが正しいか分からなくなる。SVG の `viewBox` は twip のままにしてあるので、
画面は px、印刷は mm で、同じ図をそのまま使える。

テストは `tests/unit/ruler.test.ts` / `tests/unit/trimMarks.test.ts` (寸法) と
`tests/e2e/rulerTrim.spec.ts` (画面と PDF)。
