# 実機 Microsoft Word での確認手順

自動テストで担保できるのは「Wowd が書いたものを Wowd が同じに読み直せる」ことまで。
**Word のスキーマ検証を通るかどうかは別問題**で、ここは実機でしか分からない。

開発環境に Word が無く、`soffice` も生成元ライブラリが吐いた無編集の `.docx` すら
読めないため、この確認は自動化できない。

---

## 確認用ファイルの作り方

```bash
npm run build
npm run word-check
```

`word-check/` に一式が出る。生成のあと、次の自動検査を通ってから完了する。

- zip の整合性
- 全 XML パートが整形式であること
- Wowd 自身が読み直せて、本文が空にならないこと
- 各ファイルに確認対象が実際に入っていること
  （赤入りが 2 名ぶん、コメントの返信と解決、画像の関係 ID、ヘッダー参照、目次と `w:updateFields`）

最後の検査が要点。画面操作は静かに失敗しうる（ボタンが無効、選択が外れる、など）ので、
空振りしたファイルを渡すと、確認する側の時間を無駄にしたうえで
「Word で何も出ない」という誤った結論だけが残る。

---

## いちばん大事なこと

**どのファイルも、開いた直後に次が出ないこと。**

> 「問題を修復しますか」
> 「読み取り不能なコンテンツが含まれています」

出たら、その時点でファイル名をお知らせください。以降の項目の確認は不要です。
これが出る＝ OOXML のスキーマ違反であり、他の見た目の話より優先して直します。

**「元」と「Wowd保存」のペアは両方開いてください。**

| 元 | Wowd保存 | 判断 |
|---|---|---|
| 開ける | 開ける | 正常 |
| 開ける | 開けない | **Wowd のバグ**。要報告 |
| 開けない | 開けない | 確認用ファイルを作った側の問題。要報告（Wowd のバグではない） |

この切り分けが無いと原因が特定できません。

## ファイルごとの確認項目

### 01-往復 / 02-書式と見出し / 03-表

無編集で開いて保存しただけ。**元と Wowd保存 で見た目が変わらないこと**を見ます。

1. 本文の文字が 1 字も欠けていないこと
2. **フォント名（明朝／ゴシック）と文字サイズ**が保たれていること。
   [ホーム] のフォント欄に元と同じ名前・同じ数字が出ること。
   **ここは実際に壊れていた箇所です。**開いて保存しただけで
   `w:rFonts` と `w:sz` が消えていました（修正済み・要確認）
3. 下線が**種類まで**保たれていること（二重下線が実線になっていないこと）。
   これも同じ原因で壊れていました（修正済み・要確認）
4. 太字・斜体・色・蛍光ペンが保たれていること
5. 見出しスタイルが見出しのままであること（[ホーム]→[スタイル] で選択されている）
6. 箇条書きと段落番号の記号・字下げが保たれていること
7. （03）表の結合セル・罫線・網かけが崩れていないこと

### 04-ルビ

1. ふりがなが親文字の上に出ること
2. [ホーム]→[ルビ] を開いたとき、読みが入っていること
3. 元と Wowd保存 でルビの文字サイズが変わっていないこと

### 05-原稿用紙

1. [レイアウト]→[ページ設定]→[文字数と行数] を開く
2. 「文字数と行数を指定する」が選ばれていて、**40 字 × 36 行**と出ること
3. 用紙が B5 であること

### 06-ヘッダー

1. ヘッダーに「社外秘」が右寄せで出ること
2. **先頭ページだけ**ヘッダーが「先頭ページ専用のヘッダー」になっていること
3. フッターに「- 1 -」のようにページ番号が出て、2 ページ目では「- 2 -」になること
4. [レイアウト]→[ページ設定]→[その他] で「先頭ページのみ別」にチェックが入っていること

### 07-変更履歴（書式の変更履歴）

**今回追加したファイルです。** 10 と違い、こちらは「**書式の**変更履歴」
（`w:pPrChange` / `w:rPrChange`）を含みます。Wowd 側では作れない機能ですが、
**受け取った文書には入ってきます。**

変更前の段落書式を読み捨てて規格違反の出力をしていたのを直したところなので、
**修復ダイアログが出ないことが最重要**です。

1. 開いた直後に「問題を修復しますか」が**出ないこと**
2. [校閲]→[変更履歴]→[変更内容の表示] で、
   「書式が変更された段落。」の行に**書式変更として**記録が出ること
   （「〜に書式を変更しました」のような表示）
3. [校閲]→[元に戻す]→[すべての変更を元に戻す] で、
   その段落が**見出し 1・中央揃え**に戻ること
   （変更前の書式が保たれていれば戻ります。失われていると戻りません）
4. 「文字の書式が変更された箇所」が斜体から**太字**に戻ること

### 10-変更履歴

**ここがいちばん確認したい箇所です。** 法律文書の赤入りが失われないかどうか。

1. [校閲]→[変更履歴]→[変更内容の表示] で赤入りが表示されること
2. 挿入が**下線**、削除が**取り消し線**で表示されること
3. 著者名が「校閲者A」「校閲者B」と出て、**色が別々**であること
4. [校閲]→[承諾]→[すべての変更を反映] を押すと、
   挿入が本文になり、削除された行が消えること
5. 4 を元に戻したうえで [元に戻す]→[すべての変更を元に戻す] を押すと、
   挿入が消え、削除された行が戻ること
6. 段落記号（¶）の挿入が変更として出ること
   （[ホーム]→[編集記号の表示] を入れると見えます）
7. [校閲]→[変更履歴ウィンドウ] に一覧として出ること

### 11-コメント

1. [校閲]→[コメントの表示] で**スレッドが 2 件**出ること
2. 1 件目に**返信がぶら下がっている**こと
   （別々のコメントとして並んでいたらバグ。`w14:paraId` の結び付けが壊れています）
3. 2 件目が**解決済み**として表示されること
4. コメントが付いた範囲が本文中で強調されること
5. Word 側で返信を足して保存できること

### 12-画像

1. 画像が表示されること（空欄や × 印になっていないこと）
2. 画像をクリックして図として選べること（サイズ変更のハンドルが出ること）
3. [図の形式] タブが出ること

### 13-ヘッダーフッター

06 と違い、**Wowd 側で新しく作った**ヘッダーとフッターです。

1. ヘッダーに「社外秘」が右寄せで出ること
2. フッターに「- 1 -」と出ること
3. ヘッダー領域をダブルクリックして、Word 側で編集できること
4. フッターのページ番号を選ぶと**灰色に反転する**こと（フィールドとして扱われている）
5. 2 ページ目があれば「- 2 -」になること

### 14-目次

1. 目次が表示され、ページ番号が入っていること
2. **開いたときにページ番号の更新を促されるか、自動で入っていること**
   （空欄のままならバグ。`w:updateFields` が効いていません）
3. 目次の項目を Ctrl+クリックすると該当の見出しへ飛ぶこと
4. 目次を右クリック →[フィールドの更新]→[目次をすべて更新する] が効くこと

---

## 最後に

確認が全部通ったら、**どれか 1 つを Word 側で編集して保存し直し**、
そのファイルをお送りください。Wowd がそれを壊さず開けるかを確認します。

---

## 報告のしかた

うまくいかなかった項目について、次をお知らせください。

```
ファイル名: 10-変更履歴.docx
項目番号:   3
起きたこと: 著者名が両方とも「校閲者A」になっている
Word:       Microsoft 365 / Windows 11
```

画面の写真があると助かります。特に「問題を修復しますか」が出た場合は、
**[詳細] を開いたときのメッセージ**が原因の特定に直結します。

## 逆方向の確認（Word で作ったファイルを Wowd が壊さず開けるか）

### お願いしたいファイル

Word で**新規に**文書を作り、次を入れて保存してください。

> 実際の案件ファイルではなく新規作成をお願いします。
> 内容が不要に手元を離れないようにするためです。

1. 見出し 1〜3 と本文（数ページぶん）
2. 変更履歴を記録した状態での挿入・削除（できれば 2 名ぶん。書式の変更も）
3. 返信付きのコメントと、解決済みのコメント
4. 結合セル（縦・横の両方）を含む表
5. インラインの画像
6. ルビ（[ホーム]→[ルビ]）
7. ヘッダーとフッター、ページ番号
8. 目次（[参考資料]→[目次]）
9. [レイアウト]→[ページ設定]→[文字数と行数] で文字数と行数を指定
10. 箇条書きと段落番号（複数レベル）

全部入りが 1 つでも、機能ごとに分かれていても構いません。

### 受け取ったあとの手順

`tests/fixtures/docx/` に `real-*.docx` という名前で置きます。

```bash
npm test                                   # 往復テストが自動で拾う
npm run verify:roundtrip -- tests/fixtures/docx/real-xxx.docx
```

`tests/unit/helpers.ts` の `fixtureNames()` がディレクトリを走査しているので、
**置くだけで既存のテストが全部かかります**（本文が空にならない／冪等／
パートの保持／2 回保存しても安定する／WML の子要素順序）。

`tests/fixtures/docx/*.docx` は `.gitignore` 済みなので、
置いたファイルがリポジトリに入ることはありません。

## 既知の制約（バグではないもの）

次は仕様として落としている範囲です。Word 側で差が出ても報告は不要です。

- **ページ数が Word と一致しないこと**。行分割の実装が違うため、長い文書では 1〜2 ページずれます。
  約束しているのは「Wowd の画面表示と Wowd の PDF 出力が一致すること」です
- 表がページを跨ぐときに分割されず、次ページへ丸ごと送られること
- 脚注・文末脚注がページ下部に配置されないこと（内容は保持されます）
- 画像の回り込み（インラインとして描きます。内容は保持されます）
- 段組みが 1 段で描かれること（`w:cols` は往復します）
- 和欧混植の行が原稿用紙のマス目からずれること
  （純日本語文なら指定文字数どおりに折り返します）
- 書式の変更履歴（`w:rPrChange` / `w:pPrChange`）を Wowd 側で**作れない**こと。
  読み取りと往復はします
