# 画面の広さへの追従

同じ画面を、スマホの縦・スマホの横・タブレット・半分にした窓・広いパソコンで使う。
判定は `src/renderer/hooks/useIsMobile.ts` の `useLayoutSize()` が一手に引き受け、
`.app[data-size]` として CSS にも降りてくる。**同じ判定を CSS に書かない。**
2 か所に書くと必ずずれて「CSS は詰めているのにリボンは出たまま」になる。

## 3 つの段階

| 段階 | 条件 | 主な場面 |
|---|---|---|
| `compact` | 幅 720px 以下、または 高さ 520px 以下かつ幅 1000px 以下 | スマホ (縦・横とも) |
| `medium` | 幅 1100px 以下 | タブレット、半分にした窓、最小のデスクトップ窓 |
| `full` | それより広い | 普通のパソコン |

**幅だけで決めない。** スマホを横に倒すと幅は 844px あるが高さは 390px しかない。
リボン (92px) とステータスバーを載せると本文が数行しか残らないので、
高さも見て compact に落とす。タブレットの横 (1024 × 768) は高さがあるので medium に残る。

| | compact | medium | full |
|---|---|---|---|
| 上部 | 上下のバー | リボン (詰める) | リボン |
| 紙の倍率 | 常に幅に合わせる | 収まらなければ縮める | 同左 |
| ルーラ | 出さない | 出す | 出す |
| コメント | 下からのシート | 紙の上に重ねる | 横に並べる |
| ステータスバー | バーに統合 | 文字数だけ残す | 全部出す |

## 紙が窓に収まらないとき

A4 は 794px ある。窓を狭めるとすぐ紙が右へはみ出し、横に振らないと右端が読めない。

倍率には 2 つの持ち方がある (`ZoomMode`)。

- `auto` (既定) … 収まらないときだけ縮める。収まるなら 100% のまま
- `manual` … 利用者が指定した倍率をそのまま使う

**収まるときに勝手な拡大はしない。** 窓を広げただけで文字の大きさが変わると驚く。
倍率に触れた時点で `manual` に移り、以後は黙って変えない。
ステータスバーの「幅に合わせる」で `auto` に戻せる。

ステータスバーの数字は**実際に掛かっている倍率**を出す。
指定値を出すと「100% と書いてあるのに紙が小さい」ことになる。

縦ルーラは紙の左外に置くので、そのぶん (28px) を先に差し引いてから倍率を決める。
差し引かないと、窓が狭いときに紙が左端まで寄ってルーラが切れる。
「出しているのに読めない」より、そのぶん紙を縮めるほうがまし。

## コメントを重ねる理由

280px のペインを横に並べると、1100px の窓でも本文に 800px しか残らない。
A4 (794px) がぎりぎりで、ルーラを出すと溢れる。
medium では紙の上に重ね、compact では下から出す。紙の幅は減らさない。

## スマホ特有の始末

- `viewport-fit=cover` と `env(safe-area-inset-*)`。ノッチのある端末で、
  縦ではバーが切れないように、横では左右に寄りすぎないようにする
- ダイアログは `max-width: calc(100vw - 24px)` と `max-height: calc(100dvh - 24px)`。
  `dvh` を使うのは、アドレスバーの出入りで高さが変わるため
- リボンのタブは横に流す。畳んで隠すと押せないタブが出る

## 文字がぼやける原因

`transform: scale()` を掛ける要素に `will-change: transform` を付けてはいけない。

付けるとその要素は GPU の層に固定され、文字は「層を作ったときの解像度」で
一度だけ描かれて、あとは引き伸ばされる。倍率を変えた瞬間からぼやける。
iOS の WebKit は層が大きいとさらに低い解像度で描くので、長い文書ほど眠い字になる。

付けなければ、ブラウザは `transform` 後の実寸で文字を描き直す。
倍率を変えた瞬間に描き直しが入るが、倍率はそう何度も変えない。
滑らかさより、読んでいるあいだずっとくっきりしていることを採る。

## テスト

`tests/web/responsive.spec.ts` が 8 通りの寸法で次を見る。

- 段階の判定が想定どおりか
- 横にはみ出していないか (画面と本文の両方)
- スマホを倒してもスマホ用の画面のままか
- 狭い窓で紙が縮んで収まるか、広い窓で勝手に拡大しないか
- 倍率をいじると追従をやめ、「幅に合わせる」で戻るか
- 縦ルーラが切れていないか
- コメントを開いて紙の幅が減っていないか

寸法は各テストで指定するので、`playwright.web.config.ts` の
desktop / phone のどちらで走らせても同じ結果になる (二重に走らせない)。
